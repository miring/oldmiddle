# 운영 준비

정식 운영 전에 처리해야 할 일을 모아 둡니다.

## 문자 인증 (운영 전 필수)

현재 사전 신청 폼은 **화면만** 있습니다. "인증번호" 버튼을 누르면 입력칸이 나타나지만 실제 발송·검증은 하지 않습니다. 저장 로직이 연결되기 전까지는 목업 플래그(`src/config/devFlags.ts`의 `MOCK_SMS_VERIFICATION`)로 6자리를 입력하면 통과 처리합니다. 개발 서버와 배포 사이트 모두 해당하며, 켜져 있는 동안 신청 화면 상단에 "테스트 중 · 신청 정보는 저장되지 않아요" 띠가 보입니다. 저장 로직을 붙이며 `PREREGISTER_SAVE_ENABLED`를 `true`로 바꾸면 목업 인증은 자동으로 꺼지고, 실제 인증 없이는 신청 버튼이 켜지지 않습니다. 검증 자리는 코드에 `TODO(문자 인증)` 주석으로 표시해 두었습니다.

운영 전에 할 일:

- 문자 발송 대행사와 계약 (건당 비용 발생)
- 발신번호 사전 등록
- 인증번호는 **서버에서 생성·검증** (브라우저에서 만들지 않음), 유효시간 **3분**
- 같은 번호·같은 IP의 재발송 횟수 제한 (문자 비용 남용 방지)
- 발송 대행사를 개인정보 처리방침의 **처리 위탁** 항목에 추가
- 오픈 안내를 알림톡으로 보낼 경우 카카오 비즈니스 채널 개설과 템플릿 심사
- [ ] 목업 인증 제거 확인: `MOCK_SMS_VERIFICATION`과 목업 통과 처리를 지우고, 배포 사이트에서 "테스트 중" 띠가 사라졌는지, 아무 6자리로는 통과되지 않는지 확인

## 동의서 빈칸

사전 신청 동의 [보기] 문구(`src/config/copy.ts`의 `CONSENT_COPY`)에 아직 정하지 않은 값이 `[ ]`로 남아 있습니다. 운영 전에 채우고, 문구를 고치면 `CONSENT_VERSION`(현재 `2026-11-v4`)도 올립니다.

- [ ] ① 사전 신청 안내 — `[혜택 내용·조건]`: 사전 신청 혜택과 조건
- [ ] ① 사전 신청 안내 — `[취소 방법]`: 신청 취소 방법 (예: 문자 속 링크)
- [ ] ② 개인정보 수집·이용 — `[국가]`: 신청 정보를 저장하는 서버가 있는 나라
- [ ] ② 개인정보 수집·이용 — `[업체]`: 서버(클라우드) 업체
- [ ] ③ 광고성 정보 수신 — `[발송 대행사]`: 문자·카카오톡 발송 대행사 (문자 인증 대행사와 같으면 함께 정리)
- [ ] 신청 완료 화면 혜택 카드 — `src/config/copy.ts`의 `PREREGISTER_DONE_COPY.benefit.title` (비어 있으면 카드가 숨겨짐, ① `[혜택 내용·조건]`과 같은 내용으로)
- [ ] 카카오톡 채널 주소 — `src/config/site.ts`의 `kakaoChannelUrl` (비어 있으면 완료 화면의 [카카오톡 채널 추가하기]가 숨겨짐)

## 사업자 (통신판매업, 2026-11-03 결정)

결혼중개업 신고는 하지 않고 통신판매업으로 시작합니다(기획서 11장). 푸터 사업자 정보는 `src/config/site.ts`의 `business`에 채우면 보이고, 비어 있는 줄은 숨겨집니다.

- [ ] 사업자등록 (기존 구매대행 사업자와 별도로 새로 등록, 2026-10-27 결정) → `companyName`, `representative`, `registrationNumber`
- [ ] 사업장 주소·연락처 → `address`, `phone`
- [ ] PG 가입 후 통신판매업 신고 (유료 결제 시작 전) → `mailOrderNumber`
- [ ] 유료 운영 전: 구청(여성가족 담당)이나 국민신문고에 결혼중개업 신고 대상인지 서면으로 묻고 답변 보관
- [ ] 유료 운영 시작 때 일반 추천을 자동(점수 1위)으로 전환, 운영자는 점검만
- [ ] 약관 서비스 정의는 "회원 간 만남을 위한 정보 제공 및 약속 관리 서비스"로. '결혼', '중개', '알선'이라는 말을 쓰지 않기
- 화면·알림·광고에 '결혼', '중매', '성혼', '결정사' 같은 말을 쓰지 않습니다. 만남 목적 선택지는 '진지한 교제 / 동반자 / 친구부터'만 둡니다.

## 지역 목록 갱신

행정구역이 개편되면(예: 인천 구 개편) code.go.kr에서 법정동코드 "전체자료"를 받아 `node scripts/build-regions.mjs <전체자료.txt> <기준일 YYYY-MM-DD>`를 실행해 `src/data/regions.json`을 다시 만들고 커밋합니다.

사는 지역은 이름이 아니라 코드로 저장합니다: 시·도 코드 2자리(예: `11`)와 시·군·구 코드 5자리(예: `11680`). 세종처럼 시·군·구가 없는 곳은 시·군·구 코드 칸에 시·도 코드(`36`)를 넣습니다. 오픈 지역 목록(`open_regions`)도 같은 코드로 맞춰 비교합니다. 행정구역 개편으로 코드가 바뀌면 이미 저장된 신청의 코드도 새 코드로 옮겨야 합니다.

## 사전 신청 저장 (Supabase)

신청은 브라우저가 DB에 직접 쓰지 않고 Edge Function `preregister`(`supabase/functions/preregister`)를 거쳐 저장합니다. 함수가 인증번호를 확인하고, 휴대폰 번호를 암호화(발송용)·HMAC 해시(중복 확인용)한 뒤 저장하고, 같은 지역 신청 수를 돌려줍니다.

- 프론트: `.env.local`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (`.env.example` 참고). 없으면 지금처럼 콘솔에만 찍힙니다.
- 함수 비밀 값: `PHONE_ENC_KEY`, `PHONE_HASH_KEY`, `ALLOWED_ORIGINS`, (dev 전용) `DEV_FIXED_CODE`
- **`PHONE_ENC_KEY`·`PHONE_HASH_KEY`는 따로 백업.** 잃어버리면 저장된 번호를 되돌릴 수 없어 오픈 안내를 보낼 수 없습니다. dev와 prod는 서로 다른 키를 씁니다.
- prod에는 `DEV_FIXED_CODE`를 넣지 않습니다. 넣지 않으면 실제 문자 인증을 붙이기 전까지 저장을 거부합니다(`sms_not_ready`).
- 신청 횟수 제한: 같은 번호 10분에 5번, 같은 IP 1시간에 30번 (`supabase/functions/preregister/index.ts`의 `PHONE_LIMIT`·`IP_LIMIT`). 번호·IP는 해시로만 기록하고 하루 뒤 지웁니다.
- [ ] 운영 전: 배포 주소(Vercel)를 `ALLOWED_ORIGINS`에 추가

## 사전 신청 취소·자동 파기

- **취소**: 접수 확인 메시지의 취소 링크는 `https://<사이트 주소>/#/cancel/<cancel_token>` 모양입니다. 누르면 확인 화면을 거쳐 Edge Function `preregister-cancel`이 신청을 **바로 삭제**합니다. 동의서 ①의 `[취소 방법]`은 "접수 확인 문자 속 취소 링크"로 채웁니다.
- **자동 파기**: 매일 새벽 3시(한국 시간) `pg_cron`이 동의서 기준("정식 오픈 후 6개월 또는 신청일로부터 1년 중 먼저 오는 날")이 지난 신청을 지웁니다.
- [ ] 정식 오픈일이 정해지면 SQL Editor에서 `update admin.settings set official_open_at = '<오픈일> 00:00+09';` 실행. 비워 두면 '신청 후 1년' 규칙만 적용됩니다.
- [ ] 늦게 열리는 지역 신청자에게 ③ 지역 준비 중 안내를 보낼 때 "1년 안에 열리지 않으면 정보를 지운다"는 사실을 함께 알립니다.
