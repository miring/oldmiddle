# 운영 준비

정식 운영 전에 처리해야 할 일을 모아 둡니다.

## 문자 인증 (운영 전 필수)

현재 사전 신청 폼은 **화면만** 있습니다. "인증번호" 버튼을 누르면 입력칸이 나타나지만 실제 발송·검증은 하지 않습니다. 저장 로직이 연결되기 전까지는 목업 플래그(`src/config/devFlags.ts`의 `MOCK_SMS_VERIFICATION`)로 6자리를 입력하면 통과 처리합니다. 개발 서버와 배포 사이트 모두 해당하며, 켜져 있는 동안 신청 화면 상단에 "테스트 중 · 신청 정보는 저장되지 않아요" 띠가 보입니다. 저장 로직을 붙이며 `PREREGISTER_SAVE_ENABLED`를 `true`로 바꾸면 목업 인증은 자동으로 꺼지고, 실제 인증 없이는 신청 버튼이 켜지지 않습니다. 검증 자리는 코드에 `TODO(문자 인증)` 주석으로 표시해 두었습니다.

운영 전에 할 일:

- 문자 발송 대행사와 계약 (건당 비용 발생)
- 발신번호 사전 등록
- 인증번호는 **서버에서 생성·검증** (브라우저에서 만들지 않음), 유효시간 **3분**
- 같은 번호·같은 IP의 재발송 횟수 제한 (문자 비용 남용 방지)
- 발송 대행사를 개인정보 처리방침의 **처리 위탁** 항목에 추가
- 오픈 안내를 알림톡으로 보낼 경우 카카오 비즈니스 채널 개설과 템플릿 심사
- [ ] 목업 인증 제거 확인: `MOCK_SMS_VERIFICATION`과 목업 통과 처리를 지우고, 배포 사이트에서 "테스트 중" 띠가 사라졌는지, 아무 6자리로는 통과되지 않는지 확인

## 동의서 빈칸

사전 신청 동의 [보기] 문구(`src/config/copy.ts`의 `CONSENT_COPY`)에 아직 정하지 않은 값이 `[ ]`로 남아 있습니다. 운영 전에 채우고, 문구를 고치면 `CONSENT_VERSION`(현재 `2026-10-v2`)도 올립니다.

- [ ] ① 사전 신청 안내 — `[혜택 내용·조건]`: 사전 신청 혜택과 조건
- [ ] ① 사전 신청 안내 — `[취소 방법]`: 신청 취소 방법 (예: 문자 속 링크)
- [ ] ② 개인정보 수집·이용 — `[국가]`: 신청 정보를 저장하는 서버가 있는 나라
- [ ] ② 개인정보 수집·이용 — `[업체]`: 서버(클라우드) 업체
- [ ] ③ 광고성 정보 수신 — `[발송 대행사]`: 문자·카카오톡 발송 대행사 (문자 인증 대행사와 같으면 함께 정리)

## 지역 목록 갱신

행정구역이 개편되면(예: 인천 구 개편) code.go.kr에서 법정동코드 "전체자료"를 받아 `node scripts/build-regions.mjs <전체자료.txt> <기준일 YYYY-MM-DD>`를 실행해 `src/data/regions.json`을 다시 만들고 커밋합니다.

사는 지역은 이름이 아니라 코드로 저장합니다: 시·도 코드 2자리(예: `11`)와 시·군·구 코드 5자리(예: `11680`). 세종처럼 시·군·구가 없는 곳은 시·군·구 코드 칸에 시·도 코드(`36`)를 넣습니다. 오픈 지역 목록(`open_regions`)도 같은 코드로 맞춰 비교합니다. 행정구역 개편으로 코드가 바뀌면 이미 저장된 신청의 코드도 새 코드로 옮겨야 합니다.
