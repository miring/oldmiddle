# 운영 준비

정식 운영 전에 처리해야 할 일을 모아 둡니다.

## 이메일 확인 (운영 전 필수)

2026-11-10부터 사전 신청은 **휴대폰 번호 대신 이메일**로 받습니다. 카카오 비즈니스 채널이 '만남 주선업'이라 승인되지 않아 알림톡을 쓸 수 없고, 문자도 쓰지 않기로 했습니다.

흐름: 신청 → `preregister`가 '확인 전'으로 저장하고 확인 메일 발송 → 메일 속 `#/confirm/<confirm_token>` 링크 → `preregister-confirm`이 확인을 마치고 취소 링크가 든 접수 완료 메일 발송 → 신청 완료 화면. 2일 안에 확인하지 않은 신청은 매일 새벽 자동으로 지웁니다. 신청자 수·통계는 확인을 마친 신청만 셉니다.

운영 전에 할 일:

- [ ] Resend 가입 → 도메인 `shiyeon.co.kr` 추가 → 화면에 나온 DNS 레코드(TXT·MX)를 가비아 DNS에 추가 → Verified 확인
- [ ] Resend API 키 발급 → 운영 Supabase 비밀 값 `RESEND_API_KEY`, `MAIL_FROM`(예: `시연(時緣) <noreply@shiyeon.co.kr>`) 등록 (`.env.prod`에도 같은 값)
- [ ] `npx supabase db push`, `functions deploy preregister`, `functions deploy preregister-confirm` (dev·prod 모두)
- [ ] 받는 메일함 `help@shiyeon.co.kr` 만들기 (메일의 답장 주소). 보내는 주소(Resend)와는 별개
- [ ] 네이버·다음·지메일 세 곳으로 실제 신청해 받은편지함에 오는지, 스팸함으로 가지 않는지 확인
- [ ] 위가 끝나면 `src/config/devFlags.ts`의 `PREREGISTER_SAVE_ENABLED`를 `true`로 바꿔 "테스트 중" 띠 끄기

## 지역 목록 갱신

행정구역이 개편되면(예: 인천 구 개편) code.go.kr에서 법정동코드 "전체자료"를 받아 `node scripts/build-regions.mjs <전체자료.txt> <기준일 YYYY-MM-DD>`를 실행해 `src/data/regions.json`을 다시 만들고 커밋합니다.

사는 지역은 이름이 아니라 코드로 저장합니다: 시·도 코드 2자리(예: `11`)와 시·군·구 코드 5자리(예: `11680`). 세종처럼 시·군·구가 없는 곳은 시·군·구 코드 칸에 시·도 코드(`36`)를 넣습니다. 오픈 지역 목록(`open_regions`)도 같은 코드로 맞춰 비교합니다. 행정구역 개편으로 코드가 바뀌면 이미 저장된 신청의 코드도 새 코드로 옮겨야 합니다.

## 사전 신청 저장 (Supabase)

신청은 브라우저가 DB에 직접 쓰지 않고 Edge Function `preregister`(`supabase/functions/preregister`)를 거쳐 저장합니다. 함수가 메일 주소를 암호화(발송용)·HMAC 해시(중복 확인용)해 '확인 전'으로 저장하고 확인 메일을 보냅니다. 같은 지역 신청 수는 확인을 마칠 때(`preregister-confirm`) 돌려줍니다.

- 프론트: `.env.local`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` (`.env.example` 참고). 없으면 지금처럼 콘솔에만 찍힙니다.
- 함수 비밀 값: `PHONE_ENC_KEY`, `PHONE_HASH_KEY`(이름은 예전 그대로, 이제 메일 주소에 씀), `ALLOWED_ORIGINS`, `RESEND_API_KEY`, `MAIL_FROM`, (dev 전용) `DEV_EMAIL_LINK=true`
- **`PHONE_ENC_KEY`·`PHONE_HASH_KEY`는 따로 백업.** 잃어버리면 저장된 메일 주소를 되돌릴 수 없어 오픈 안내를 보낼 수 없습니다. dev와 prod는 서로 다른 키를 씁니다.
- prod에는 `DEV_EMAIL_LINK`를 넣지 않습니다. 메일 키가 없으면 저장을 거부합니다(`email_not_ready`). dev에서 `DEV_EMAIL_LINK=true`면 메일 대신 확인 링크가 응답으로 와 브라우저 콘솔에 찍힙니다.
- 신청 횟수 제한: 같은 메일 10분에 3번, 같은 IP 1시간에 30번 (`supabase/functions/preregister/index.ts`의 `EMAIL_LIMIT`·`IP_LIMIT`). 메일·IP는 해시로만 기록하고 하루 뒤 지웁니다.
- [x] 운영 `ALLOWED_ORIGINS`: `https://shiyeon.co.kr,https://www.shiyeon.co.kr` (2026-11-10). 메일 속 링크도 신청한 사이트 주소로 만들어집니다

## 사전 신청 취소·자동 파기

- **취소**: 접수 완료 메일의 취소 링크는 `https://<사이트 주소>/#/cancel/<cancel_token>` 모양입니다. 누르면 확인 화면을 거쳐 Edge Function `preregister-cancel`이 신청을 **바로 삭제**합니다. 동의서 ①의 취소 방법은 "접수 완료 메일 속 취소 링크"로 채웠습니다.
- **자동 파기**: 매일 새벽 3시(한국 시간) `pg_cron`이 동의서 기준("정식 오픈 후 6개월 또는 신청일로부터 1년 중 먼저 오는 날")이 지난 신청과, 확인 메일을 보낸 지 2일이 지나도록 확인하지 않은 신청을 지웁니다.
- [ ] 정식 오픈일이 정해지면 SQL Editor에서 `update admin.settings set official_open_at = '<오픈일> 00:00+09';` 실행. 비워 두면 '신청 후 1년' 규칙만 적용됩니다.
- [ ] 늦게 열리는 지역 신청자에게 ③ 지역 준비 중 안내를 보낼 때 "1년 안에 열리지 않으면 정보를 지운다"는 사실을 함께 알립니다.
